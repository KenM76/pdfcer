# textedit — provenance and attribution

Nine minimal PDFs, generated byte by byte by
`tools/gen-textedit-fixtures.py`:

- **Five for Pass 14.1** (in-place text edit — content-stream surgery +
  single-line relayout + the font-on-edit refusal gate,
  `pdfcer_core::text_edit::edit`): `nonembedded.pdf`, `embedded_full.pdf`,
  `subset_missing.pdf`, `tagged.pdf`, `tm_follower.pdf`.
- **Three for Pass 14.2** (in-place FORMATTING — size / fill colour /
  font-family-style, `pdfcer_core::text_edit::format`): `format_color.pdf`,
  `format_other.pdf`, `format_family.pdf`. `tagged.pdf` is reused for the
  Pass-14.2 tagged anti-corruption case (a colour change on a tagged run).
- **One for Pass 142.1** (the font-resource pre-flight,
  `EditSession::preview_font_resources` / `pdfcer font-preflight`):
  `format_twins.pdf`. `format_family.pdf` is reused for the pre-flight's
  per-run acceptance cases.

## Source material and license (LEGAL.md §5)

**No structural byte here derives from a third-party PDF.** Every file's
object layout, cross-reference table, page tree and content stream is
authored in the committed generator, with no PDF library behind it (same
discipline as the sibling `tools/gen-*-fixtures.py`). The visible text is
placeholder English ("teh quick brown fox", "the cat", "Hello World")
carrying no expressive content — LEGAL.md §5 category (a), **wholly
synthetic**, CC0-equivalent.

### Embedded font program (two files) — rights-cleared, category (b)

`embedded_full.pdf` and `subset_missing.pdf` embed a font **program** as a
`/FontFile3 /Subtype /Type1C` stream, because Pass 14.1's font-on-edit gate
distinguishes an embedded run (edit within the program's coverage) from an
embedded **subset** run (refuse a glyph the subset does not already carry).
The embedded bytes are a **verbatim copy of a bundled Foxit Base-14 face**,
`crates/pdfcer-render/assets/fonts/FoxitSans.cff` — already in this
repository and already rights-cleared for redistribution (its own
provenance is `crates/pdfcer-render/assets/fonts/PROVENANCE.md`; the Foxit
standard-14 substitute faces are distributed with pdfcer under that grant).
Re-using an already-cleared in-repo asset keeps the whole corpus
synthetic/rights-cleared with **no new third-party material** introduced.

- `embedded_full.pdf`: `/BaseFont /Helvetica` (no subset tag) ⇒ the gate
  reports `GlyphSource::Embedded`, and the edited page renders with the
  document's own embedded glyphs (`render-page` reports `substituted=0`).
- `subset_missing.pdf`: `/BaseFont /ABCDEF+Helvetica` (a §9.6.4 subset tag)
  ⇒ the gate treats it as an embedded subset. The program bytes are the
  same Foxit CFF; the *subset* semantics are driven by which codes the page
  actually uses, not by physically subsetting the program (pdfcer-core never
  parses the embedded program — R21), which is exactly what the
  "already carries" floor keys on.

## Regenerating

```text
python tools/gen-textedit-fixtures.py
```

Deterministic — no timestamps, no `/ID`, no random values. Running it twice
produces byte-identical files. Requires a Python interpreter and the in-repo
`FoxitSans.cff` (read for the two embedded fixtures).

|---|---|
| `nonembedded.pdf` | The **most-editable** case + the trust-level disclosure. A NON-embedded `/Calibri` simple font (`/WinAnsiEncoding`, explicit `/Widths`, `/FontDescriptor` with no `/FontFile*`). Editing `teh`→`the` succeeds and is disclosed `Bundled`; with `--font-dir` supplying a `Calibri` face it is disclosed `Supplied` (decision 012 — shapes only; positions still from `/Widths`). |
| `embedded_full.pdf` | Editing within an **embedded-full** program's coverage. `/Helvetica` with an embedded `/FontFile3 /Type1C` program (no subset tag). `teh`→`the` renders correctly via the document's own glyphs; only the edited content stream changes. |
| `subset_missing.pdf` | The **one refusal** in decision 014's four-case table. `/ABCDEF+Helvetica`, embedded subset; the page carries only `{t,h,e,space,c,a}`. Editing `cat`→`caz` asks for `z`, which the subset does not already carry ⇒ **REFUSED by name** (`R-INV-1` embedded-subset floor — Acrobat's "embedded-but-not-local" floor). |
| `tagged.pdf` | **Tagged-PDF disclosure** (R72). The run sits inside `/P << /MCID 0 >> BDC … EMC` (catalog `/MarkInfo << /Marked true >>`). Editing `teh`→`the` PRESERVES the BDC/EMC+MCID wrapper (structure references stay valid) and DISCLOSES that `/ActualText`/reading-order went stale — pdfcer discloses rather than silently corrupting, beating Acrobat. |
| `tm_follower.pdf` | The **absolute-`Tm` follower** relayout (surgery ref §3). Two runs on one line: `Hello ` (`Td`) then `World` re-anchored by `1 0 0 1 240 700 Tm`. Editing `Hello`→`Hi` shortens the run, so the follower `Tm`'s `e` operand is reduced by |ΔA| (`followers_repositioned=1`), and `World` stays flush. |

## The Pass 14.2 formatting files

| File | The one thing it pins |
|---|---|
| `format_color.pdf` | A NON-embedded `/Calibri` run `hello world` painted BLUE (`0 0 1 rg`). Pins TWO things: (1) a **size** change (`--set-size 24`) touches ONLY the `Tf` operand — the `0 0 1 rg` blue survives byte-verbatim and no new colour operator is added; (2) a **colour** change STORES THE CHOSEN DEVICE SPACE — `--set-color cmyk:0,1,1,0` emits a `0 1 1 0 k` operator, NOT a force-converted `rg` (parity-plus over Acrobat, which always stores DeviceRGB). |
| `format_other.pdf` | A run `hello world` whose fill colour is set in a NON-DEVICE space — a `/Separation` colour space `/CS0` (`/CS0 cs 0.7 scn`), which pdfcer records as `TextColor::Other`. A `--set-color rgb:1,0,0` change is **DISCLOSED as a space-narrowing conversion** (`fill_narrowed=1`, never silent — rule 4), and the run's tail is restored to the original `/CS0 cs 0.7 scn` sequence **byte-verbatim**. The Separation carries a valid Type-2 tint transform (`1..0` DeviceGray) so the page still renders. |
| `format_family.pdf` | A `/Times-Roman` run `hello world` on a page that ALSO carries two other font RESOURCES. `/F2` (`/Calibri-Bold`, WinAnsi, `/Widths`) is a **fully-covering** target: `--set-font F2` succeeds, swaps the `Tf` to `/F2`, and re-encodes the run (disclosed `Bundled`, or `Supplied` with `--font-dir` supplying a `Calibri-Bold` face). `/F3` (`/Times-Bold` whose `/Encoding /Differences` remaps code 111 `o` to `/bullet`) does NOT cover `o`, so `--set-font F3` is **REFUSED by name** (`U+006F 'o'`) with nothing applied. `--set-font Nonexistent` is refused as a missing resource. No embedding ever happens (subsetting is FF-C). |
| `format_twins.pdf` | A `/Times-Roman` run `hello world` on a page carrying **TWO resources with the SAME `/BaseFont /Times-Bold`** — two independent subsets of one face, the shape a real embedding producer emits routinely (`pdfcer-gui`'s own survey found it in **87 %** of embedding files). `/FB1`'s `/Encoding /Differences` remaps code 111 `o` to `/bullet` and so does NOT cover the run; `/FB2` is the same `/BaseFont` with a plain WinAnsi encoding and DOES. Pins three things nothing else here can: (1) **a `/BaseFont` is not a usable `--set-font` selector when a page carries two of them** — the name match reaches exactly one twin, so the pre-flight reports the **resource key** and flags the ambiguity; (2) **acceptance is a property of the RESOURCE, not of the name** — two identical `/BaseFont` values, opposite verdicts; (3) **the synthesis gate must name `/FB2`**, because `/FB1` refuses the very edit a refusal naming it would recommend (`Pass 144.0`). |

## What must come out (acceptance, decision 014 §5.2 "13.2")

- `format_color.pdf` → `--set-size 24` succeeds: `set_size=12->24`,
  `set_color=none`, the output is an incremental **prefix** of the input,
  `/F1 24 Tf` present, `0 0 1 rg` untouched. `--set-color cmyk:0,1,1,0`
  succeeds: `set_color=k`, output contains `0 1 1 0 k`.
- `format_other.pdf` → `--set-color rgb:1,0,0` succeeds with
  `fill_narrowed=1`, a `NARROWING` disclosure, and `/CS0 cs 0.7 scn`
  restored verbatim in the output.
- `format_family.pdf` → `--set-font F2` (or `Calibri-Bold`) succeeds with
  `set_font=Times-Roman->Calibri-Bold` and `/F2 12 Tf`; with `--font-dir`
  supplying `Calibri-Bold` it is disclosed `glyph_source=Supplied`.
  `--set-font F3` exits `EDIT_REFUSED` (9) naming `U+006F`; `--set-font
  Nonexistent` exits 9 as a missing resource. Nothing is written on either
  refusal.
- `format_twins.pdf` → `font-preflight --find "hello world"` reports `/FB1`
  REFUSE and `/FB2` ACCEPT, both with `selector` equal to the **resource key**
  and both flagged `ambiguous /BaseFont`; the summary offers
  `--set-font "FB2"` as the real bold. `format_family.pdf` →
  `font-preflight --find "hello world"` reports no real bold of the run's
  family (because `/F3` refuses), and `--find "hell"` reports `/F3` ACCEPT
  with selector `Times-Bold` — the same face, the same page, opposite answers,
  which is the whole argument for a per-run pre-flight.
- `tagged.pdf` → `--set-color rgb:1,0,0` succeeds; `tagged_mcid=0`, the
  output still contains `/MCID 0`, and an `R72` disclosure reports the
  structure tree went stale (the anti-Acrobat-tag-corruption property).

## What must come out (acceptance, decision 014 §5.2)

- `nonembedded.pdf` → edit succeeds; `glyph_source=Bundled`, or `Supplied`
  with `--font-dir`; re-extraction shows `the quick brown fox`.
- `embedded_full.pdf` → `glyph_source=Embedded`; re-extraction shows
  `the cat`; `render-page` shows `substituted=0`; the input file is a
  byte-identical **prefix** of the incremental output (untouched objects
  verbatim).
- `subset_missing.pdf` → exit `EDIT_REFUSED` (9) with the `R-INV-1`
  embedded-subset message; no output written.
- `tagged.pdf` → edit succeeds; report shows `tagged_mcid=0`; the output
  still contains `/MCID 0`; re-extraction shows `tagged=true`.
- `tm_follower.pdf` → `advance_delta < 0`, `followers_repositioned=1`;
  re-extraction shows `Hi World`.
