# annot — provenance and attribution

Sixteen minimal PDFs for Pass 6.0 (annotation appearance **rendering**,
read-side; ISO 32000-1 §12.5, `docs/decisions/008`). Each file isolates
**one** claim from the appearance-display contract — the §12.5.5
placement algorithm from both directions, the §12.5.3 display flags, the
`/Popup` non-paint rule, R43 named-not-painted, `/AS` state selection,
and the X8 appearance-resource-scoping trap — so a failing test names the
clause it broke rather than reporting that "annotations are wrong".

## Source material and license (LEGAL.md §5)

**Nothing here derives from a third-party file.** These are `LEGAL.md`
§5 category (a): **wholly synthetic**, authored for this project,
generated byte by byte by a committed script
(`tools/gen-annot-fixtures.py`) with no PDF library behind it — so the
fixtures cannot inherit a bug (or a normalization) from the very code
they test, and no attribution is owed or claimed. Every file is a single
200×200-unit page with a classic §7.5.4 cross-reference table.

Every appearance stream fills its **entire `/BBox`** solid black, which
is what makes placement assertable from the raster alone: the painted
region on the page is exactly the image of the `/BBox` under the §12.5.5
transform, so "is the stamp in the right place?" reduces to a pixel
check. No embedded font programs are used except in
`ap-resources-own-font.pdf`, whose two fonts are the non-embedded
standard-14 faces Helvetica and Times-Roman (§9.6.2.2 permits omitting
`/Widths` and `/FontDescriptor` for the standard 14) — pdfcer draws these
with its bundled substitute faces and the fixture asserts on *which*
substitute was chosen, not on glyph shapes.

## Annotation DELETION (Pass 38.5) — three later additions

Written by a **second** script, `tools/gen-annot-deletion-fixtures.py`,
and kept apart from the sixteen above on purpose: those pin a *display*
contract on 200×200 pages where every appearance fills its `/BBox` solid
black, and none of that serves a deletion test. Folding these into the
Pass 6.0 generator would have meant one script with two unrelated page
conventions.

Same `LEGAL.md` §5 category (a) as the rest of this directory: wholly
synthetic, byte-authored, no PDF library involved, no attribution owed.

| File | Claim it makes falsifiable |
|---|---|
| `thread.pdf` | The three deletion cascades. One 300×300 page, 7 annotations: a `/Square` **primary** (obj 4) with a `/Popup` companion (5), an **explicit** `/RT /R` reply (6), an **implicit** reply with no `/RT` at all (7 — Table 170's default is `R`, so this is the one that catches an implementation reading absence as "not a reply"), a `/RT /Group` **subordinate** (8), and two `/Stamp`s (9, 10) that **share one appearance stream** (12). Deleting object 4 must remove 5, un-link 6/7/8, and take stream 11; deleting stamp 9 must **not** take stream 12, and deleting 10 afterwards must. |
| `certified-p3.pdf` | `/P 3` — *"the same as for 2, as well as annotation creation, deletion, and modification"* (§12.8.2.2 Table 254). **The corpus's first `/P 3` file**, and `delete_annotation` is the first pdfcer operation any `P` value permits. Carries one `/Square` and one form field, so "annotation delete allowed, field delete still refused" is assertable on one document. |
| `certified-p2-annot.pdf` | The falsifier for the row above — the same file with one digit changed. Without it, "permitted at `/P 3`" is equally consistent with the annotation verb never consulting the certification at all (R162). **The existing `forms/certified-p2-form.pdf` cannot serve**: it contains only widgets, so the annotation verb's widget refusal fires before the certification gate is reached. |

## Deletion of things that are NOT annotations (Pass 190.1) — three files

Written by `tools/gen-annot-structural-fixtures.py`. Same `LEGAL.md` §5
category (a): a fuzzer's mutation of pdfcer's own generated bytes is
pdfcer's own bytes; nothing was downloaded.

**These were shipped in `Pass 190.1` and this table was not written at the
time** — recorded here in `Pass 191.0`, which found the omission while
adding its own neighbours. Noted rather than quietly backfilled, because a
provenance file that is silently incomplete is worse than one that is
visibly late: `LEGAL.md` §5 makes this table the *record* that every
fixture is rights-clean, and an unlisted file is indistinguishable from an
undocumented download.

| File | Claim it makes falsifiable |
|---|---|
| `structural-annots-catalog.pdf` | A page whose `/Annots` names the **document catalog**. The reduced 173-byte crash input, closed so it loads. `delete_annotation` deleted the catalog and returned `Ok`; the deletion must now be refused **by name**, and the page tree must still walk afterwards. |
| `structural-annots-pages-node.pdf` | The `BadKid` signature — the same defect with a **page-tree node** in `/Annots`. Separate from the file above because it reaches the page-tree half of the guard rather than the `/Type` half. |
| `structural-annots-mixed.pdf` | ★ The control. A real `/Square` **beside** a structural entry in one `/Annots`, so a "fix" that refuses every deletion fails. Without it the two files above would pass on an engine that had stopped working entirely. |

## `/AP` cascade type safety (Pass 191.0) — five files

Written by `tools/gen-annot-ap-cascade-fixtures.py`; `LEGAL.md` §5
category (a), byte-authored, no PDF library involved.

`delete_annotation`'s cascade 3 collects the objects an annotation's `/AP`
reaches and deletes them, and it never checked that any of them was a
**stream**. ISO 32000-1 §12.5.5: *"Each appearance stream is a form
XObject"*, and a Table 168 subdictionary *"shall define multiple appearance
streams"* — so every object that cascade reaches shall be a stream.

| File | Claim it makes falsifiable |
|---|---|
| `ap-cascade-widget-reaches-page.pdf` | The measured reproducer, minimized. `/AP /N` names a `/Widget` **dictionary**, so the old code took the appearance-state-subdictionary branch and harvested the widget's `/P` — the **page**. Deleting the `/Stamp` must not delete the page. |
| `ap-cascade-names-catalog.pdf` | `/AP /N` names the **catalog** directly, whose `/Pages` was then harvested. A distinct route: it destroys the page tree without the collected object ever being a `/Page`, which is what makes a name-based blacklist insufficient and a type test necessary. |
| `ap-cascade-single-stream.pdf` | ★ Control. A genuine, solely-owned appearance stream that **must still be deleted** — otherwise the defect is "fixable" by admitting nothing, and every deletion orphans a stream. |
| `ap-cascade-state-subdict-ref.pdf` | ★ Control for the branch that broke: `/N` is a **reference to** a state subdictionary whose members really are streams. Same resolved type as the hostile file, opposite required outcome. Stops the fix degenerating into "a dictionary under `/N` is always suspect". |
| `ap-cascade-state-subdict-inline.pdf` | ★ Control for the inline twin: `/N` written as a **direct** dictionary. A different code path, kept separate because a guard applied to one branch and not the other is a shape this project has shipped before. |

## Regenerating

```
python tools/gen-annot-fixtures.py             # the sixteen Pass 6.0 files
python tools/gen-annot-deletion-fixtures.py    # the three Pass 38.5 files
python tools/gen-annot-structural-fixtures.py  # the three Pass 190.1 files
python tools/gen-annot-ap-cascade-fixtures.py  # the five Pass 191.0 files
```

The scripts are the single source of truth; do not hand-edit the `.pdf`
files. Deleting and regenerating them must be a byte-for-byte no-op
(both writers are deterministic).
