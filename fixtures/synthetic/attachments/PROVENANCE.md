# attachments — provenance and attribution

Eleven minimal PDFs for the embedded-file (attachment) **reader** in
`crates/pdfcer-core/src/attachments.rs` (ISO 32000-1 §7.11 file
specifications and embedded file streams, §7.7.4/§7.9.6 name trees,
§12.5.6.15 file attachment annotations).

Each file isolates **one** claim about that reader, so a failing test
names the claim it broke rather than reporting that "attachments are
wrong". The claims fall into four groups: the two *structurally
different* attachment mechanisms and the requirement that a reader tell
them apart; the name-precedence rules; the declared-vs-actual size
question; and hostile / malformed input.

## Source material and license (LEGAL.md §5)

**Nothing here derives from a third-party file.** These are `LEGAL.md`
§5 category (a): **wholly synthetic**, authored for this project,
generated byte by byte by a committed script
(`tools/gen-attachment-fixtures.py`) with no PDF library behind it — so
the fixtures cannot inherit a bug (or a normalization) from the very code
they test, and no attribution is owed or claimed. Every file is a
`%PDF-1.7` document with the §7.5.2 binary comment and a **classic**
§7.5.4 cross-reference table, one or two blank 200×200 pages, and no
fonts, images, or content streams at all.

Every embedded payload is inert ASCII text of the author's invention
(`hello attachment\n`, `payload for alpha.txt\n`, 4096 `A`s). **No file
here contains an executable, an archive, a script, or any real-world
document.** That is deliberate beyond the licence question: a fixture
corpus for an attachment reader is exactly the kind of thing an
antivirus scanner examines, and exactly the kind of thing that must
never contain a payload that could be mistaken for a live one.

The single non-hand-rolled step is `zlib.compress` for
`flate-size-truth.pdf` (§7.4.4 delegates `/FlateDecode` to RFC 1950).
Hand-authoring a deflate stream would add nothing but the chance of a
typo, and the fixture's point is precisely that the *encoded* and
*decoded* lengths differ.

Regenerate with `python tools/gen-attachment-fixtures.py`. CC0.

## What each file pins

### The two mechanisms, and telling them apart

| File | Structure | Claim it pins |
|---|---|---|
| `doc-level-simple.pdf` | catalog `/Names /EmbeddedFiles`, **flat** root node | the document-level walk happens at all, and every §7.11.3/§7.11.4 optional key is surfaced: `/F`, `/UF`, `/Desc`, `/Subtype`, `/Params` `/Size` `/CreationDate` `/ModDate` `/CheckSum` |
| `page-level-annot.pdf` | one `/FileAttachment` annotation; **no `/Names` in the catalog at all** | the page-level mechanism is not missed. A reader that only walks the name tree reports this document as having no attachments — the central conflation failure |
| `both-kinds.pdf` | 2 pages: one document-level entry + one annotation on **page 2** | both kinds come back in one list, labelled differently, with the correct zero-based `page_index` (1, not 0) |
| `annot-contents-beats-desc.pdf` | **one** filespec carrying `/Desc`, reached **both** ways; the annotation's `/Contents` says something different | §12.5.6.15's clause-unique `shall`: "Conforming readers shall use this entry rather than the optional `Desc` entry … in the file specification dictionary". Two rows, two descriptions, one dictionary — and the rows must **not** be de-duplicated because they share a `filespec_id` |

The `/Subtype` in `doc-level-simple.pdf` is written `/text#2Fplain`,
because `/` cannot appear literally in a name (§7.3.5) and a MIME type
contains one. A reader that does not apply `#` escapes reports the media
type wrong.

### Name precedence

| File | Structure | Claim it pins |
|---|---|---|
| `doc-level-unicode-name.pdf` | key = `tree-key-differs.txt`, `/F` = `resume.txt`, `/UF` = UTF-16BE `résumé-Σ.txt` — **three different strings on purpose** | `/UF` wins over `/F` wins over the name-tree key, and `/UF`'s UTF-16BE bytes are decoded as UTF-16BE and not as Latin-1 |
| `doc-level-kids-tree.pdf` | root (`/Kids` only, no `/Limits`) → 2 intermediate nodes → 3 leaves, all non-root nodes carrying `/Limits` | the §7.9.6 tree is walked through its interior. A reader that only reads the root's `/Names` finds nothing here |
| `ef-platform-slots.pdf` | **no `/F` and no `/UF`** — only `/DOS`, `/Mac`, `/Unix`, and an `/EF` containing only `/Unix`. The shape ISO 32000-1's own §7.11.4 EXAMPLE uses | Table 44 makes `/F` required *only* when all three platform entries are absent, so this is **conforming**. A reader consulting `/F`/`/UF` alone reports a nameless attachment with no bytes in a legal document |

On `doc-level-unicode-name.pdf`: note that the sourcing pass **refuted**
the premise that an `/EmbeddedFiles` key must be a text string
(`EF-N1`). Table 31 states no encoding requirement, the sibling
`/Renditions` row in the same table *does*, and §7.9.6 says "any
encoding of the keys may be used as long as it is self-consistent". The
fixture uses a plain-byte key while `doc-level-simple.pdf` uses a
UTF-16BE one — both are legal, and neither is what the attachment is
*called*.

### Declared vs. actual size

These two are a **matched pair** and must be read together: one must be
reported as disagreeing and the other must not.

| File | Structure | Claim it pins |
|---|---|---|
| `size-lies.pdf` | `/Params /Size 999999` over a **10-byte unfiltered** stream | `/Size` is a declaration, not a measurement, and the lie is provable at listing time without decoding anything |
| `flate-size-truth.pdf` | `/FlateDecode`, `/Params /Size 4096` (the true **decoded** size), `/Length` far smaller | a reader that validates `/Size` against `/Length` cries wolf on every compressed attachment. The only correct listing-time verdict is "unverified"; decoding must then settle it in the document's favour |

### Hostile and malformed input

| File | Structure | Claim it pins |
|---|---|---|
| `hostile-names.pdf` | four entries: `..\..\..\Windows\System32\evil.exe`, `/etc/cron.d/pwn`, `ok.txt\0.exe`, `CON.txt` | the listing reports names **verbatim** (a reader that quietly repaired them would be lying about the document), and the sanitiser neutralises all four. None of these names is illegal PDF — §7.11.2 does not forbid them and a name-tree key is an arbitrary byte string |
| `degenerate.pdf` | five malformations plus one good entry: a `/Kids` cycle back to the root, a filespec with no `/EF` (legal — an external file reference), an `/EF /F` dangling reference, an odd-length `/Names` array, and a tree value that is an integer | nothing is fatal, nothing hangs, nothing is silent. The good entry survives all five, the external and dangling entries are **listed** (an attachment the document names but cannot deliver is information, not noise), and every degradation is counted in `AttachmentNotes` |

The NUL entry in `hostile-names.pdf` earns a note of its own, because it
caught a real defect in the first implementation. `0x00` is **undefined
in PDFDocEncoding**, so by the time `/F`'s bytes have been through
§7.9.2 text-string decoding the NUL is a U+FFFD REPLACEMENT CHARACTER —
and a sanitiser that checked only `char::is_control` waved the
extension-spoof straight through. The fixture is why
`NameHazard::UndecodableBytes` exists.

## What these fixtures deliberately do NOT cover

Recorded so a later reader knows these are gaps and not oversights:

- **`/RF` related-files arrays** — the reader does not model them, so no
  fixture exercises them.
- **`/Params /Mac`** (Table 47) — the Mac resource-fork triple.
- **Encryption.** Nothing here is encrypted, so
  `AttachmentNotes::may_be_encrypted` is only ever exercised in its
  `false` state. The case that most needs a fixture is the nastiest one:
  §7.6.5's `/EFF` + `DefEmbeddedFile`, which encrypts embedded files
  inside an *otherwise unencrypted* document. Writing it requires the
  encryption writer, so it is deferred rather than dismissed.
- **PDF Portfolios** (`/Collection`, §12.3.5). A portfolio's files *are*
  ordinary document-level embedded files and would list correctly, but
  no fixture carries a `/Collection` dictionary.
- **Object streams and xref streams.** Every fixture uses a classic
  §7.5.4 table, matching the rest of `tools/gen-*-fixtures.py`.
