# cmyk-variants — provenance and attribution

Six minimal single-page PDFs sharing ONE entropy-coded JPEG payload,
varying only (a) the Adobe APP14 transform byte and (b) the presence of
`/Decode [1 0 1 0 1 0 1 0]`. They pin decision 006's conclusions
(`docs/decisions/006-cmyk-jpeg-inversion.md` §3.4/§6.4): pdfcer never
applies an "Adobe CMYK inversion" (R29), the YCCK inverse is
definitional not polarity (TN #5116 §13.1), and `/Decode` composes as
the sole polarity control. They are the durable evidence replacing the
throwaway survey/probe scripts (006 §11 method note).

## Construction (reproducible from this note alone)

JPEG payload variants (all length-preserving, so every byte offset
survives):

| Variant | Patch |
|---|---|
| `v2` | none — the original codestream (APP14 `Adobe`, version 100, flags 0/0, **transform byte 2** = YCCK; byte offset 17 within the codestream, i.e. APP14 segment at offset 2, transform = 12th payload byte) |
| `v0` | transform byte 2 → **0** (raw CMYK) at that same offset |
| `vn` | APP14 marker byte `0xEE` → `0xFE` (**COM**), turning the segment into a same-length comment — the "no Adobe marker" case |

Each payload is wrapped in a minimal 5-object PDF 1.7 file (catalog →
pages → page → content → image XObject), MediaBox `[0 0 300 232]`,
content stream `q 300 0 0 232 0 0 cm /Im0 Do Q` — the image at **1:1**,
so a scale-1.0 render maps one sample to one pixel and polarity
assertions need no resampling allowance. The `_dec` twin of each adds
`/Decode [1 0 1 0 1 0 1 0]` to the image dictionary; nothing else
differs.

## What the tests assert (`crates/pdfcer-render/tests/cmyk_variants.rs`)

- Decoded CMYK sample values at named pixels (v2 pixel(2,2) =
  `[0,3,6,0]`, centre = `[81,25,8,1]`; v0 pixel(2,2) =
  `[253,126,130,0]` — the raw stored `(Y,Cb,Cr,K)`), because sample
  values are exactly what a silent `zune-jpeg` passthrough-semantics
  change would break (006 §9 revisit trigger 5).
- Pixel-level render polarity for the `/Decode` variants: each `_dec`
  render is the §8.9.5.2 inversion of its plain twin's polarity
  (v2 light/correct vs v2_dec dark; likewise v0/vn pairs), pinning the
  signed-slope `/Decode` ramp in `pdfcer-render/src/image.rs`.
