# ink-probe — provenance and attribution

Two single-page PDF fixtures pinning the **ink probe**
(`RenderOptions::with_ink_probe`, `pdfcer render-page --probe-ink`) and,
through it, one claim about the colorant compositor that had never been tested
directly: **for a single opaque paint over an empty page, a correct colorant
composite is the identity on its operand.**

Generated by `tools/gen-ink-probe-fixtures.py`; used by
`crates/pdfcer-render/tests/ink_probe.rs` and
`crates/pdfcer-cli/tests/render_page.rs`.

## The two files

| file | page group | what pdfcer does with it |
|---|---|---|
| `flat-cmyk-subtractive.pdf` | `/Group << /S /Transparency /CS /DeviceCMYK >>` | composites in the four-colorant buffer |
| `flat-cmyk-additive.pdf` | none | composites on screen, in sRGB |

Everything else about the two pages is byte-identical — same media box, same
geometry, same `0.75 0 1 0 k` operand, same object numbering — so any
difference in a measurement is attributable to the blending space and to
nothing else.

## Why the second file is a control and not decoration

A probe implementation that reported the **content stream's** operands rather
than the **buffer's** contents would satisfy every assertion made against the
first page. It cannot satisfy the second, where there is no colorant buffer at
all and the only honest report is *"there are no colorant values"* — a
different answer, not a smaller one.

## Why this operand

`0.75 0 1 0` is a saturated green. A neutral would have been useless: a colour
near the achromatic axis barely moves through a bad `CMYK → sRGB → CMYK` round
trip, so a fixture built on one passes whether or not the defect is there
(`R225` — a fixture whose two candidate answers coincide cannot distinguish
them).

It is also the operand of the patch whose colour raised the question these
fixtures answer, so the synthetic and the real file are asking about the same
number.

## Rights

Rights-cleared by construction: every byte is produced by the generator
(`docs/LEGAL.md` §5). No external content, no third-party artwork, no fonts.

## Regenerating

```
python tools/gen-ink-probe-fixtures.py
```

Deterministic — no timestamps, no random data, no `/ID`. Re-running it on an
unchanged script reproduces byte-identical files, so a diff in this directory
always means the generator changed.
