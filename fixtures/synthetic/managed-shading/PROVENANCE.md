# managed-shading — provenance and attribution

Six single-page PDF fixtures pinning that **a shading and a mesh convert their
colour through the same bridges a fill does** — an `ICCBased` colour through
its embedded profile, a `Lab` colour through the output intent (`Pass 243.0`).
Generated by `tools/gen-managed-shading-fixtures.py`; used by
`crates/pdfcer-render/tests/managed_shading.rs`.

The shading counterpart of `fixtures/synthetic/icc-rgb/` and
`fixtures/synthetic/lab-ink/`, and the last member of the family
`fixtures/synthetic/mesh-ink/` started: one colour, several object types, one
page, agreement as the oracle.

## The files

Each page is 300 × 100 pt and paints one colour three ways: a flat fill at
x 10–90, a constant axial (type 2) shading at x 110–190 whose two stops are
both that colour, and a type 4 free-form triangle mesh at x 210–290 whose
every vertex is that colour.

| file | space | page group | `/OutputIntents` |
|---|---|---|---|
| `icc-rgb-shading-additive.pdf` | `[/ICCBased swap-rg.icc]` | none | none |
| `icc-rgb-shading-subtractive.pdf` | same | `/CS /DeviceCMYK` | `dest-cmyk.icc` |
| `icc-rgb-shading-subtractive-no-intent.pdf` | same | `/CS /DeviceCMYK` | none |
| `lab-shading-additive.pdf` | `Lab` D50 `/Range [-128 127 -128 127]` | none | none |
| `lab-shading-subtractive.pdf` | same | `/CS /DeviceCMYK` | `dest-cmyk.icc` |
| `lab-shading-subtractive-no-intent.pdf` | same | `/CS /DeviceCMYK` | none |

Operands, samples and expected values are exactly those of the two sibling
directories — `(0.4, 0.2, 0.8)` through the swap-RG profile, managed
`(48, 102, 205)` against unmanaged `(102, 51, 204)`; `Lab (60, 0, 0)`, whose
press separation is chromatic where `rgb_to_cmyk`'s is K-only — so the three
fixture families cannot drift apart. Both profiles are READ from
`fixtures/synthetic/icc-rgb/` at generation time, never regenerated here; see
that directory's `PROVENANCE.md` for both files' provenance (the RGB profile
is generated by this project; the CMYK one is the author's own MIT-licensed
iccce fixture, byte for byte).

## Why a constant ramp

Two identical stops make every sample of the ramp the fill's colour, so the
swatch can be sampled anywhere inside and the test measures the ROUTE rather
than the interpolation. The mesh is two flag-0 triangles covering the swatch
with every vertex at the same colour, for the same reason. Interpolation is
pinned by `fixtures/synthetic/shading/` and `mesh-ink/`.

## What each page discriminates

* ICC additive: the display bridge in `ColorRamp::build` and
  `mesh::read_shade`. Without it the shading and mesh land on `(102, 51, 204)`
  beside a fill at `(48, 102, 205)` — 54 levels apart in red (R225).
* ICC subtractive with intent: the ink bridge in both; the intent-less twin
  differs only in `/OutputIntents`, so a probed ink that does not move between
  them means the bridge never ran.
* Lab subtractive with intent: the PCS bridge in both — chromatic ink
  (`0.24 0.24 0.24 0.16`) against the control's K-only `(0, 0, 0, 0.43)`.
* Lab additive: the control that pins nothing moved where no route exists.
