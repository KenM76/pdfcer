# deletion-collateral — provenance and attribution

Eighteen minimal PDFs that **size** the eight deletion-collateral sites the
`Pass 191.0` audit named but did not fix. Twelve are hostile inputs, one per
claim; seven are controls (one file, `dim-sidecar-ap-names-pagetree.pdf`,
carries two claims, and `dim-sidecar-control.pdf` controls for two sites).

Generated by `tools/gen-deletion-collateral-fixtures.py`; measured by
`crates/pdfcer-core/examples/collateral_probe.rs`.

## The defect class

`Pass 191.0` fixed one instance of:

> A verb dereferences a dictionary key, assumes the pointee is the kind of
> object that key is defined to hold, and **deletes it** — or deletes and
> overwrites objects reached through it.

There, `/AP` `/N` named a `/Widget` dictionary; the deletion cascade harvested
that widget's `/P` (which names the **page**), deleted the page, returned `Ok`,
and `to_full_bytes` wrote a file that reloads with `PageTreeError::BadKid`.
Nothing complained in a release build, because
`debug_assert_page_tree_still_walks` is `#[cfg(debug_assertions)]`.

The audit run under `R219` — enumerate the class rather than wait for the next
fuzz finding — named eight more sites. These files are what turned each claim
into a measured yes or no.

## Source material and license (LEGAL.md §5)

**Nothing here derives from a third-party file.** `LEGAL.md` §5 category (a):
**wholly synthetic**, authored for this project, generated byte by byte by a
committed script with no PDF library behind it — so a fixture cannot inherit a
bug (or a normalization) from the very code it falsifies. No attribution is
owed or claimed.

Every file is a single 300×300-unit page with a classic §7.5.4 cross-reference
table: no xref streams, no object streams. A fixture that needs a
compressed-object parser to be read is testing two things at once, and when one
of them fails you cannot tell which.

The one borrowed byte-blob is the sfnt donor
`fixtures/synthetic/text/subset-fstype-editable.ttf`, embedded in the two
`cidset-*.pdf` files. It is itself a tracked synthetic font this repository
authored. It is needed because site 8 requires a **genuinely removable embedded
font** alongside the poisoned `/CIDSet`: the `/FontFile*` sibling **is**
type-guarded (`fontinfo.rs` — `let Object::Stream(stream) = resolved else {
NotAStream }`), so a font whose program is not a real stream never becomes a
removable target and `/CIDSet` is never reached.

## Why the trap is almost always object 2, the page-tree root

Two reasons, and the second is the one that matters to whoever writes the fix.

1. Deleting the **root** produces `NoPageTreeRoot` — an unambiguous, total loss
   no fail-clean recovery path can paper over. Deleting a `/Kids` member
   produces `BadKid`, equally fatal today, but a future recovery pass could
   plausibly learn to drop a bad kid and still open the file.
2. It proves the reach is **not special to `/Page` dictionaries**. Several of
   these verbs would be *partially* protected by a `/Type /Page` name test —
   `annotation_deletion_guards` has exactly such a test — and a fix that only
   added one would look green against a page-shaped trap.
   `refuse_if_in_page_tree` covers the page, **its ancestors and the catalog**;
   these files are shaped to require that, not a name comparison.

Two files deviate deliberately: `flatten-field-is-page.pdf` (reproducing
`Pass 185.1`'s literal input, where the collision *is* with a `/Page`) and
`outline-item-is-page.pdf` (whose whole claim is that the entry gate admits a
`/Page` **because a `/Page` carries `/Parent`**).

## Terminology (project rule 15)

The `dim-sidecar-*.pdf` files concern **ce dimensions** — the `/Line` + `/IT
/LineDimension` annotations pdfcer authors, with their `/PieceInfo` sidecar.
No **pdf dimension** (a measurement a CAD exporter drew into page content) is
involved anywhere in this directory; page content is not reachable by key from
any of these verbs.

## What each file pins

### Hostile — sidecar-driven ce-dimension verbs (sites 1, 2)

| File | Poisoned key | Verb | Claim |
|---|---|---|---|
| `dim-sidecar-ap-names-pagetree.pdf` | sidecar `/Ap` → obj 2 | `delete_dimension` | `record.ap` enters `removals` untested; the page-tree root is **deleted** |
| `dim-sidecar-ap-names-pagetree.pdf` | sidecar `/Ap` → obj 2 | `set_dimension_label` | `regenerate_dimension_writes` **overwrites** obj 2 with a form XObject — a *label edit* destroys the page tree |
| `dim-sidecar-annot-names-pagetree.pdf` | sidecar `/Annot` → obj 2 | `delete_dimension` | `record.annot` enters `removals` untested; obj 2 carries a stray `/P` so the verb's only lookup succeeds |

The only validation a sidecar passes through is
`check_dimension_sidecar`, which compares `/Version` against
`SIDECAR_VERSION` and looks at nothing else. It does not resolve `/Annot`, does
not resolve `/Ap`, and does not ask what either points at.

### Hostile — annotation and form verbs (sites 3, 4, 6)

| File | Poisoned key | Verb | Claim |
|---|---|---|---|
| `redact-ap-names-pagetree.pdf` | `/AP` `/N` → obj 2 | `delete_redaction_mark` | `/N` taken as a reference with no type test (§12.5.5: *"Each appearance stream is a form XObject"*) |
| `redact-mark-is-pagetree-node.pdf` | `annot_id` **is** obj 2 | `delete_redaction_mark` | the verb runs **none** of `annotation_deletion_guards`; obj 2 wears `/Subtype /Redact` and `redaction_marks` finds it |
| `flatten-field-is-page.pdf` | `/AcroForm` `/Fields` → obj 3 | `flatten_fields` | `Pass 185.1`'s literal input in the one form verb that never received `refuse_if_in_page_tree` |
| `popup-is-pagetree-node.pdf` | `/Popup` → obj 2 | `delete_annotation` | the `/Popup` id joins `removing` **after** the guards have run; §12.5.6.14 says `/Popup` is a pop-up annotation, nothing checks |

### Hostile — outline and attachment verbs (sites 5, 7)

| File | Poisoned key | Verb | Claim |
|---|---|---|---|
| `outline-first-names-pagetree.pdf` | `/First` → obj 2 | `delete_outline_item` | `outline_subtree` walks `/First`/`/Next` unconditionally and pushes every dictionary it reaches; it is depth- and cycle-guarded but not **type**-guarded, and those are different properties |
| `outline-item-is-page.pdf` | caller names obj 3 | `delete_outline_item` | the only entry gate refuses an object with **no** `/Parent`; every `/Page` has one (§7.7.3.3 Table 30, required). This document has no outline at all |
| `attach-namevalue-is-pagetree.pdf` | name-tree value → obj 2 | `detach_file` | the reference is doomed on array position alone (§7.7.4 Table 31: a name tree of **file specifications**) |
| `attach-ef-is-pagetree.pdf` | `/EF` `/F` → obj 2 | `detach_file` | one hop further in, and the more realistic shape — the value **is** a `/Type /Filespec`. §7.11.4 Table 45: each `/EF` value *"shall be an embedded file stream"* |

### Hostile — font unembedding (site 8)

| File | Poisoned key | Verb | Claim |
|---|---|---|---|
| `cidset-names-pagetree.pdf` | `/FontDescriptor` `/CIDSet` → obj 2 | `unembed_fonts` | `out.cid_set_id = cid_set.as_reference()` with no type test, chained into the freed set beside the font program. §9.7.4.2 Table 117 defines `/CIDSet` as a **stream** |

The contrast with its `/FontFile*` sibling is the point: both keys are read off
the same descriptor, in the same function, ten lines apart; one is guarded and
one is not. `/CIDSet` on a *simple* font is malformed (§9.8.1 Table 124 puts it
on a CIDFont descriptor) and is here on purpose, for the reason
`gen-unembed-fixtures.py` gives for its own `unembed-charset-cidset.pdf`: phase
A never classifies a composite font `Removable`, so a conforming document
cannot present "removable font whose descriptor carries `/CIDSet`", and the
handling exists anyway.

### Controls — and why they are not optional

| File | Verb(s) that must still succeed | What it must still do |
|---|---|---|
| `dim-sidecar-control.pdf` | `delete_dimension`, `set_dimension_label` | free obj 4 + 5 / rewrite obj 5's stream; page tree intact |
| `redact-control.pdf` | `delete_redaction_mark` | drop obj 4 from `/Annots`, free obj 4 **and** its `/AP` obj 5 |
| `flatten-control.pdf` | `flatten_fields` | burn 1 widget, register obj 5 as a page resource, free obj 4, **keep** obj 5 |
| `outline-control.pdf` | `delete_outline_item` | relink `/Prev`/`/Next` around the hole, decrement `/Count`, free obj 5 |
| `popup-control.pdf` | `delete_annotation` | delete the pop-up **with** its parent (§12.5.6.14 *"shall not appear alone"*; §12.5.6.2 NOTE 2) |
| `attach-control.pdf` | `detach_file` | drop the name-tree pair, free obj 4 + 5, dedup the `/F`/`/UF` alias |
| `cidset-control.pdf` | `unembed_fonts` | strip `/FontFile2`, `/CharSet`, `/CIDSet`; free **both** obj 7 and obj 8 |

The cheapest way to make all twelve hostile files behave is to refuse
everything — which would silently break ce-dimension deletion, redaction-mark
rejection, form flattening, bookmark deletion, comment deletion, attachment
detachment and font unembedding, all at once, and pass the hostile set while
doing it. `gen-annot-ap-cascade-fixtures.py` states the same reasoning for its
own three controls out of five; this set follows it deliberately.

**A run where a hostile row is clean and a control row is not has not measured
a fix. It has measured a regression.**
