# transparency — provenance and attribution

Single-page PDF fixtures for **image transparency rendering** —
`pdfcer-render`'s `/SMask`, `/Mask` (stencil and colour-key) and `/Matte`
compositing (`crates/pdfcer-render/src/mask.rs`). Used by
`crates/pdfcer-render/tests/image_transparency.rs`.

Sibling of `fixtures/synthetic/images/`, which holds the *raster* fixtures
for the import direction. Both are produced by the same script for the same
reason: they answer one question — "did the alpha survive?" — from the two
ends of the pipeline, and letting them drift apart would let a change in one
half quietly stop testing the other.

## Source material and license (LEGAL.md §5, project rule 7)

**Nothing here derives from a third-party file.** These are `LEGAL.md` §5
category (a): **wholly synthetic**, authored for this project, generated by
a committed script (`tools/gen-image-fixtures.py`, its
`transparency_pdfs()` section) from pixel data this project chose — four
solid-colour texels and a four-step alpha ramp. No attribution is owed or
claimed, and nothing was downloaded from anywhere.

The PDFs are assembled **byte by byte** from a classic §7.5.4 cross-reference
table with no object streams and no compression on the structure, so a
failing test can be diagnosed in a hex editor and a fuzzer mutating one keeps
producing something a parser will engage with.

## How to regenerate

```
python tools/gen-image-fixtures.py
```

Writes both `fixtures/synthetic/images/` and this directory. Requires Pillow
only for the JPEG fixtures in the sibling directory; nothing here needs it.

## The design, and why it is the way it is

Two decisions carry the whole suite. Both are recorded here because a future
edit that "simplifies" either one silently removes the suite's ability to
fail.

### 1. The backdrop is PURE BLUE, and the image is PURE RED

**A renderer that ignores alpha entirely passes a white-on-white
transparency test.** Composite a transparent image over a white page and the
correct output and the broken output are the same pixels — which is exactly
the state `pdfcer-render` was in before this Pass, and exactly why the defect
survived a full image-rendering Pass with pixel tests.

So every page here paints an opaque pure-blue rectangle first and places a
pure-red image over it. tiny-skia stores premultiplied RGBA and composites
`SourceOver`, so:

```
dst' = src + dst x (1 - a)
src  = premultiplied pure red at alpha a = (a, 0, 0, a)
dst  = opaque pure blue                  = (0, 0, 255, 255)
dst' = (a, 0, 255 - a, 255)
```

The rendered pixel's **red channel is the applied alpha** and its blue
channel is 255 minus it. The tests read the alpha back directly rather than
asserting a colour that happens to encode one.

### 2. The alpha ramp is 0 / 85 / 170 / 255, never binary

Binary alpha cannot catch a premultiplication bug: at `a = 0` and `a = 255`
a `min`-clamp and a multiply agree. The two intermediate values are the only
ones that separate them — and a `min`-clamp where a multiply belonged was a
real, live bug in `image::premultiplied` until this Pass, invisible to every
black-and-white test.

## Geometry

A 100 x 40 pt page. A 4 x 1 image placed by `80 0 0 20 10 10 cm`, so each
image column occupies a 20 pt band. At render scale 1.0 the four band centres
are device pixels (20, 20), (40, 20), (60, 20) and (80, 20) — far from any
band boundary, so nearest-neighbour sampling and anti-aliasing cannot make a
probe ambiguous.

Object numbering is fixed across every file: 1 Catalog, 2 Pages, 3 Page,
4 Contents, 5 the image XObject (`/Im0`), 6 the mask stream where there is
one.

## The files

Each isolates ONE decision, so a failure names its own cause.

| File | Pins |
|---|---|
| `smask-ramp.pdf` | The main event. `/SMask`, matching dimensions, 8-bit `DeviceGray`. Alpha applied AND premultiplied. |
| `smask-decode.pdf` | `/Decode [1 0]` on the mask — §8.9.5.2's inversion idiom applied to alpha. A build that `min`/`max`-normalizes the pair (correct for a `/BBox` per §7.9.5, catastrophic here) renders this identically to `smask-ramp.pdf`. |
| `smask-small.pdf` | A 2 x 1 mask over the 4 x 1 base. Table 145: dimensions are "independent" absent `/Matte`; both images map to the unit square "regardless of whether the samples coincide individually." Indexing 1:1 reads past the end and inverts which half vanishes. |
| `smask-large.pdf` | An 8 x 1 mask over the 4 x 1 base. The odd sample indices carry the ramp and the even ones carry a decoy value of 9, so a `floor(i x mw / bw)` mapping (no half-texel offset) renders every band at alpha 9. |
| `smask-16bit.pdf` | A 16-bit mask. Table 145 puts no value restriction on the mask's `/BitsPerComponent`, and pdfcer's own importer writes one for a 16-bit RGBA PNG. |
| `smask-indexed.pdf` | `/SMask` over an `/Indexed` base — the palette fast path is a separate arm of the pixel loop and needs its own proof. |
| `smask-matte.pdf` | `/Matte` (Table 146), undone per §11.6.5.3's `c = m + (c' - m)/a`. **The matte is WHITE deliberately**: with a black matte the preblend reduces to `c' = a x c`, which is exactly tiny-skia's own premultiplied storage, so a black-matte fixture renders identically whether the inversion runs or not. |
| `smask-matte-mismatch.pdf` | `/Matte` with mismatched dimensions. Table 145 makes equality a **shall** when `/Matte` is present, so the inversion is dropped by name while the alpha still applies. |
| `smask-rgb-refused.pdf` | A three-component `/SMask`. Table 145: "Required; shall be `DeviceGray`". Refused by name — there is no defined rule for reducing three components to one alpha and picking one would be an invention. |
| `stencil-mask.pdf` | `/Mask` as a stream (§8.9.6.3), 1-bit, samples 0,1,0,1. §8.9.6.3 never names a sample value; it defers to §8.9.6.2, where the default `/Decode [0 1]` makes **0 mark the page** — so 0 SHOWS the base image. The opposite of the "1 means set" bitmap intuition, and the opposite of a soft mask's 0. |
| `stencil-mask-decode.pdf` | The same stencil with `/Decode [1 0]`. Rendering these two identically is the classic silent-inversion bug: the mask hides exactly the half it was meant to reveal, and the result looks deliberate rather than broken. |
| `colour-key.pdf` | `/Mask` as an array (§8.9.6.4) over a red/green/red/blue strip, masking pure red. Position-independent: it is the COLOUR that vanishes. This is what a single-transparent-colour PNG (`tRNS` on truecolour) becomes. |
| `colour-key-indexed.pdf` | The same over an `/Indexed` image, where n is **1** (the index), not the base space's 3 — so the array is two integers. A reader using the base space's count calls it malformed and masks nothing. |

## `gs /SMask` REPLACES; it does not intersect (Pass 192.0)

Written by `tools/gen-smask-replace-fixtures.py`; same `LEGAL.md` SS5 category (a) as everything above -- byte-authored, no PDF library involved.

ISO 32000-1 Table 58's `/SMask` row: altering the soft mask with `gs` *"completely replaces the old value with the new one, rather than intersecting the two as is done with the current clipping path"*. pdfcer folds a mask into the clip by multiplication, which is a sound way to apply ONE mask and a wrong way to apply two.

| File | Claim it makes falsifiable |
|---|---|
| `smask-replaces-not-intersects.pdf` | Two soft-masked fills in ONE q-level with **no `q`/`Q` between them** -- the shape a bevel-and-emboss uses. Their masks cover disjoint halves, so if a second `/SMask` multiplies onto the first the product is 0 and the second layer paints NOTHING. Hard halves rather than the real case's complementary gradients, deliberately: it makes this a colour test (left red, right blue) instead of a tolerance test. |
| `smask-single-layer-control.pdf` | * The control: ONE masked layer, which must render identically. The fix touches the path every single-mask document uses, so without this "the second layer now paints" is equally consistent with a change that broke masking altogether. |

Regenerate with `python tools/gen-smask-replace-fixtures.py`; the writer is deterministic, so regenerating must be a byte-for-byte no-op.

## Spot colorants in transparency groups (`Pass 239.0`)

Generated by `tools/gen-group-spot-fixtures.py`; wholly synthetic (`LEGAL.md`
§5 category (a)). Used by `crates/pdfcer-render/tests/group_spot_planes.rs`.
Each page draws the same paint twice, directly and through the construct
under test, so the assertion is agreement and needs no reference render.

| File | Pins |
|---|---|
| `spot_in_isolated_group_vs_fill.pdf` | a spot fill inside an isolated group reaches the parent's plane for that colorant BY NAME — a decoy spot is painted first so the two rosters disagree on index |
| `spot_in_nonisolated_group_vs_fill.pdf` | the two-walk non-isolated route carries spot planes through §11.4.4's removal and allocates a colorant the parent has never seen |
| `spot_under_knockout_group_vs_direct.pdf` | a knockout group's initial backdrop carries the spot planes beneath it; the element multiplies against them |
